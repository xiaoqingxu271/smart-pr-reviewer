# 研发代码安全规范（样例）

> 本文件为 RAG 检索的规范库样例，条款编号格式：SEC-<三位序号>。
> 切块策略：二/三级标题为块边界，rule_id 取条款编号；一条款一件事。
>
> 每条都带「典型违规」示例：检索的 query 是代码，条款正文是中文制度文字，
> 两者不同分布会让绝对相似度落在无关代码的分数带里（实测见
> `experiments/rag-embedding-bench.md`）。示例代码把条款拉回与代码同侧的表征，
> 是比调阈值更根治的做法。示例为通用写法，非测试用例原文。

## SEC-001 禁止硬编码密钥与密码

任何密码、API Key、Token、数据库连接串不得硬编码在源码中——凭据只要以字面量形式
写死在代码或配置文件里即视为违规，必须改为通过环境变量或密钥管理服务获取。
发现硬编码一律标记为 **high** 风险。本条约束的是**凭据的来源**，与是否对外输出无关。

典型违规：

```python
DB_PASSWORD = "Adm1n!2024-prod"
client = OpenAI(api_key="sk-proj-a1b2c3d4")
conn_str = "postgres://admin:Passw0rd@10.0.0.8:5432/prod"
SECRET = "ghp_x7k..."        # 写死在模块常量里
```

正确写法：

```python
DB_PASSWORD = os.environ["DB_PASSWORD"]      # 或从密钥管理服务读取
```

## SEC-002 SQL 查询禁止字符串拼接

禁止使用 f-string、`%` 或 `+` 拼接 SQL 语句，必须使用参数化查询
（如 `cursor.execute(sql, params)`）。拼接 SQL 标记为 **high** 风险。

典型违规：

```python
query = f"SELECT id FROM accounts WHERE name = '{user_name}'"
cursor.execute("DELETE FROM logs WHERE uid = %d" % uid)
```

正确写法：

```python
cursor.execute("SELECT id FROM accounts WHERE name = ?", (user_name,))
```

## SEC-003 禁止不安全的反序列化

禁止对不可信数据使用 `pickle.loads` / `yaml.load`（非 safe）。应使用 `json` 或
`yaml.safe_load`。标记为 **high** 风险。

典型违规：

```python
payload = pickle.loads(request.body)
conf = yaml.load(raw_text)
```

正确写法：

```python
payload = json.loads(request.body)
conf = yaml.safe_load(raw_text)
```

## SEC-004 子进程调用必须限制 shell

`subprocess` 调用禁止 `shell=True` 且命令参数来自用户输入；外部输入必须经过
白名单校验。违反标记为 **high** 风险。

典型违规：

```python
subprocess.run(f"convert {upload_name} out.png", shell=True)
os.system("ping " + host)
```

正确写法：

```python
subprocess.run(["convert", safe_name, "out.png"], shell=False)
```

## SEC-005 文件路径必须校验穿越

拼接用户输入的文件路径时，必须校验 `os.path.realpath` 结果不逃逸出允许目录
（防 `../../` 路径穿越）。违反标记为 **medium** 风险。

典型违规：

```python
target = os.path.join(BASE_DIR, filename_from_request)
data = open(target).read()
```

正确写法：

```python
target = os.path.realpath(os.path.join(BASE_DIR, name))
if not target.startswith(os.path.realpath(BASE_DIR) + os.sep):
    raise ValueError("path outside allowed directory")
```

## SEC-006 禁用弱哈希与禁用证书校验

密码存储禁用 md5/sha1，应使用 bcrypt/argon2；HTTP 请求禁止 `verify=False`。
违反标记为 **medium** 风险。

典型违规：

```python
digest = hashlib.md5(password.encode()).hexdigest()
requests.get(url, verify=False)
```

正确写法：

```python
pwd_hash = bcrypt.hashpw(password.encode(), bcrypt.gensalt())
requests.get(url, verify="/etc/ssl/certs/ca.pem")
```

## SEC-007 敏感信息输出脱敏

日志、异常信息与报告输出中不得回显明文密码或完整 token；展示密钥类值必须脱敏
（保留前 4 位）。本条约束的是**对外输出**，不是取值方式。

典型违规：

```python
logger.info(f"login failed password={pwd}")
print("full token:", full_token)
raise RuntimeError(f"auth error, secret={secret_value}")
```

正确写法：

```python
logger.info("login failed for user=%s", user)
logger.info("token=%s****", token[:4])
```

## SEC-008 禁止对不可信输入执行代码

禁止 `eval` / `exec` 处理外部输入，禁止把用户数据当代码执行；需要表达式计算时
必须使用受限解释器或白名单运算符。标记为 **high** 风险。

典型违规：

```python
total = eval(formula_from_request)
exec(user_supplied_script)
obj = __import__(module_name)
```

正确写法：

```python
total = safe_arithmetic.evaluate(formula_from_request)   # 受限表达式求值器
```

## SEC-009 前端输出必须转义防 XSS

向 DOM 写入外部内容时禁止直接赋值 `innerHTML`，必须转义或使用 `textContent`；
富文本需过白名单过滤器。标记为 **high** 风险。

典型违规：

```javascript
commentEl.innerHTML = userInput;
document.write(paramFromUrl);
```

正确写法：

```javascript
commentEl.textContent = userInput;
```
