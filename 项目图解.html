项目一 · 单点工具化 M1–M6 全里程碑已落地

PR 智能审查与总结工具

输入 PR Diff，输出 风险点 · 修改建议 · 关联规范条款 · PR 摘要 的结构化报告，每个 issue 可定位到真实行号、可追溯到规范条款。

输入（三种来源）
本地仓库 · GitHub PR · GitLab MR
→
输出
PRReviewResult（JSON）+ Markdown 报告
目标：漏洞召回 ≥ 80% 干净 PR 误报 ≤ 2 ≤2000 行 PR 端到端 < 2 分钟
流水线阶段 ◆难点（技术硬骨头） ★亮点（可讲的设计）
◆ 难点
解析 hunk 头 @@ -a,b +c,d @@，把每个变更行映射为新文件绝对行号；纯删除行无新行号。
◆ 难点
三来源格式差异大（Git 文本 / GitHub diff / GitLab 逐文件 JSON），需统一为同一结构。
1
Diff 提取 · 噪音过滤
diff_extractor.py · sources.py
解析 unified diff → 变更文件清单 + 每文件变更行号区间。
★ 亮点
锁文件 / 二进制 / vendor / 生成代码自动跳过，跳过规则可配置并记录原因。
★ 亮点
Token 只走环境变量、不入库；三来源统一输出 DiffResult，后续无感知。
▼
◆ 架构基石 · 核心矛盾
Diff hunk 默认只有 3 行上下文，不足以做 AST；AST 又需要完整文件，但整文件送审 token 成本爆炸。「精确定位」与「完整语法」必须组合。
2
读取变更文件完整内容
sources.py · load_contents
按 head ref 取可审查文件的完整源码，供 AST 解析。
★ 亮点
只取 reviewable 文件：git show ref:path / contents API 精确取数，取不到就跳过、不中断。
▼
◆ 难点
PR 代码本身可能有语法错误，ast.parse 会失败，需逐级降级而非报错。
◆ 难点
巨函数（如 3000 行）需二级切分，且绝不能按字符/固定行数硬切。
3
AST 智能分块（三级降级链）
chunker.py
① Python ast 函数/类边界 → ② 其他语言边界正则 → ③ 按行窗口兜底；只切含变更行的块。
★ 核心亮点
AST 分块函数切断率 0%（按行硬切 99%，见实验 1），从结构上消除上下文丢失误判。
★ 亮点
装饰器行计入块起始；类头与方法分离；未变更块仅以签名级 context 附带。
▼
◆ 难点
规范是中文语料，Chroma 默认 MiniLM 中文效果差；相似度阈值需按实际 embedding 重标定。
◆ 难点
检索为空时，禁止把空结果伪造成规范依据。
4
RAG 规范检索
rag.py
以代码块为 query，top-k=3 检索内部规范条款，结果可为空。
★ 亮点
bge-m3 中文 embedding；规范文件 hash 变化时自动重建索引。
★ 亮点
ChromaDB 缺失自动降级 JSON 存储；HashEmbedder（词袋+中文二元组）让测试离线可跑。
▼
◆ 难点
幻觉：LLM 会编造不存在的文件、行号与条款号。
◆ 难点
代码注释/字符串可实施 Prompt 注入（如 "ignore previous instructions"）。
5
LLM 结构化审查
reviewer.py · llm/
每块输出结构化 JSON；解析失败带错误信息重试，最多 2 次。
★ 核心亮点
三重幻觉后校验：文件白名单 / 行号块范围 ±10 / 条款存在性；丢弃数计入 hallucination_filtered 可观测。
★ 亮点
json_schema 结构化输出，网关不支持时自动降级；OpenAI / Ollama 双后端（本地隐私模式）。
▼
◆ 难点
同一问题被多个块重复报告；总输入超 100k token 预算需分批审查后合并。
6
合并去重 · LLM 汇总
reviewer.py · pipeline.py
跨块去重、风险排序、生成 ≤200 字 PR 摘要。
★ 亮点
同文件 + 行号差 ≤3 + 同类型判为重复，保留描述更详细的一条；按 high→low 排序。
★ 亮点
LLM 摘要失败有模板兜底，不阻断出报告。
⚙ 横切服务层：FastAPI 异步服务（api/main.py）
异步任务 + 轮询
POST /review 立即返回 id → GET /review/{id} 查状态（queued/running/completed/failed）→ 下载 /report。
diff hash 缓存
以请求内容 hash 为 key，24h TTL，相同 diff 不重复消耗 token。
配置与探活
Pydantic Settings 统一配置；/health 探测 LLM 与 ChromaDB 状态。
密钥脱敏
报告检测到硬编码密钥时仅保留前 4 位，其余以 **** 遮盖。
